# Architecture

## System overview

```
┌─────────────────────────────────────────────┐
│  Windows PC (running MSFS/P3D/FSX + vPilot)  │
│                                               │
│   ┌───────────┐     ┌────────────────────┐  │
│   │  vPilot   │────▶│  RemoteControl.dll  │  │
│   │ (IBroker) │◀────│  (this plugin)      │  │
│   └───────────┘     └──────────┬──────────┘  │
│                                 │ WebSocket    │
│                                 │ :9001        │
└─────────────────────────────────┼────────────┘
                                   │  LAN
                    ┌──────────────┴─────────────┐
                    │                             │
              ┌─────▼─────┐               ┌───────▼──────┐
              │  Mac App   │               │   iOS App    │
              │ (SwiftUI)  │               │  (SwiftUI)   │
              └────────────┘               └──────────────┘
```

Plus an outbound-only call from the plugin to `https://data.vatsim.net/v3/vatsim-data.json` (public, unauthenticated, polled every 30s) for live controller positions.

## Plugin (C#)

Implements `RossCarlson.Vatsim.Vpilot.Plugins.IPlugin`. Responsibilities:

1. **Event bridge** — subscribes to `IBroker` events (`NetworkConnected`, `NetworkDisconnected`, `RadioMessageReceived`, `PrivateMessageReceived`) and serializes each to JSON.
2. **WebSocket host** — a `System.Net.HttpListener` bound to `+:9001` (all interfaces, configurable), upgraded per-connection to `WebSocket`. Binding to anything other than `localhost` requires a URL ACL reservation or admin rights, which the installer configures automatically (see `installer/VPilotRemoteControl.iss`); without it, the plugin falls back to `localhost`-only and logs a warning. Broadcasts to all connected clients; no fan-out queue, so a slow client can block a broadcast tick (see [Known limitations](#known-limitations)).
3. **Airspace watcher** — a timer polls VATSIM's data feed, computes great-circle distance (Haversine) from current aircraft position to each online controller's position, and estimates time-to-intercept from ground speed. Fires an `airspace_alert` event when ETA ≤ 5 minutes.
4. **Command handler** — deserializes incoming client JSON (`{"action": "connect", ...}`) and calls the matching `IBroker` method.

### Why WebSocket over HTTP polling
Message and alert events are push-driven and need to reach the app within a second or two (a controller calling you is time-sensitive). Polling would add latency and battery drain on iOS for no benefit, since we already control both ends.

### Why local, not cloud, for MVP
Keeps the initial build scope small and avoids handling VATSIM credentials or personal position data outside a device you control. A relay server (for true WAN/cellular use when away from your LAN) is a deliberate v2 feature — see [SESSION_PLAN.md](SESSION_PLAN.md) and the note in [Known limitations](#known-limitations).

## Message protocol

All messages are JSON over the WebSocket, one object per frame.

**Plugin → App**
```json
{ "type": "state_change", "isConnected": true, "callsign": "BAW123", "timestamp": "..." }
{ "type": "radio_message", "from": "EGLL_TWR", "message": "...", "frequencies": [118500], "timestamp": "..." }
{ "type": "private_message", "from": "N123AB", "message": "...", "timestamp": "..." }
{ "type": "airspace_alert", "controller": "EGLL_APP", "frequency": "119.730", "timeToIntercept": 4.2, "distance": 38.1, "timestamp": "..." }
```

**App → Plugin**
```json
{ "action": "connect", "callsign": "BAW123", "typeCode": "B738", "selcal": null }
{ "action": "disconnect" }
```

`RequestConnect(callsign, typeCode, selcalCode)` and `RequestDisconnect()` are vPilot's real `IBroker` methods (confirmed against vPilot's published plugin SDK). Critically, vPilot authenticates with VATSIM itself — CID/password live in vPilot's own settings, not the plugin API — so **no credentials ever cross the WebSocket**. The `connect` command only asks an already-signed-in vPilot to go online with a given callsign/aircraft type/SELCAL.

Every payload carries a `"v": 1` field for schema versioning.

## Security model

This is the part to take seriously before distributing publicly:

- **No authentication on the WebSocket.** Anyone on your LAN who can reach port 9001 can issue `connect`/`disconnect` commands or read your message traffic. There are no credentials to steal (see above), but someone could still force your session online/offline with a callsign of their choosing, or read your private messages.
- **Plaintext transport**: all traffic is unencrypted `ws://`. Acceptable only because it's LAN-local in the MVP. Before any WAN exposure, this must move to `wss://` (TLS) at minimum.
- **Planned mitigation (post-MVP):** pairing token generated by the plugin on first run (shown in vPilot's debug console or a QR code), which the app must present on connect. This turns "anyone on the LAN" into "anyone who's seen the token," which is a meaningful bar.
- **Recommendation for contributors:** don't add a WAN relay without also adding authentication — track these together, not sequentially.

## Known limitations

- Broadcasting is synchronous per-client (`.Wait(1000)`); a hung client stalls the loop for others. Fine for 1–2 personal devices, not for a public multi-user tool. A proper fix is a bounded async send queue per client.
- The Swift client reconnects with exponential backoff (1s → 30s cap) when the socket drops unexpectedly, but there's no reachability check — on a fully dead network it'll keep retrying indefinitely rather than pausing, which is fine for a personal LAN tool but worth knowing.
- Airspace alert distance is a straight-line ETA using current ground speed and heading is *not* factored in — this will report false positives when flying parallel to, rather than toward, a controller's position. Acceptable for MVP; flagged for improvement.
- Live aircraft position (lat/lon/altitude/ground speed) requires SimConnect, which is *not* part of `IBroker`. The plugin needs its own SimConnect client running alongside the IBroker subscription — this is non-trivial and is scoped as its own session (see SESSION_PLAN.md).
